# Custom & Extended Components

This document provides a complete reference of all components in this library that either **extend shadcn/ui beyond its defaults** or are **fully custom components with no shadcn/ui equivalent**.

---

## Part 1: shadcn-Based Components with Extended Functionality

These components exist in shadcn/ui but have been significantly enhanced in this library with additional variants, props, and behaviors.

---

### `Button`

**shadcn variants:** `default`, `destructive`, `outline`, `secondary`, `ghost`, `link`

#### Extra Variants (not in shadcn)

| Variant   | Behavior                                                                      |
| --------- | ----------------------------------------------------------------------------- |
| `solid`   | Filled solid background, fully themeable via the `color` prop                 |
| `soft`    | Light tinted background with colored text (e.g. `bg-danger-soft text-danger`) |
| `surface` | Transparent with a colored border; fills with color on hover                  |

#### `color` Prop (not in shadcn)

Works across all variants — `solid`, `soft`, `surface`, `outline`, `ghost`, `link`:

- **Design tokens:** `primary`, `secondary`, `tertiary`, `destructive`, `info`, `danger`, `success`, `warning`, `muted`, `accent`
- **Raw Tailwind palette:** `gray`, `red`, `orange`, `amber`, `yellow`, `lime`, `green`, `emerald`, `teal`, `cyan`, `sky`, `blue`, `indigo`, `violet`, `purple`, `fuchsia`, `pink`, `rose`

```tsx
<Button variant="solid" color="danger">Delete</Button>
<Button variant="soft" color="success">Approve</Button>
<Button variant="surface" color="info">Info</Button>
<Button variant="outline" color="warning">Warning</Button>
```

#### Extra Props (not in shadcn)

| Prop               | Type                                                  | Description                                             |
| ------------------ | ----------------------------------------------------- | ------------------------------------------------------- |
| `leftIcon`         | `ReactNode`                                           | Icon rendered left of label; hidden during loading      |
| `rightIcon`        | `ReactNode`                                           | Icon rendered right of label; hidden during loading     |
| `isLoading`        | `boolean`                                             | Disables button and shows a spinning icon               |
| `loadingText`      | `string`                                              | Replaces label text when `isLoading` is true            |
| `wrapperClassName` | `string`                                              | Class for the inner flex wrapper around label and icons |
| `unstyled`         | `boolean`                                             | Strips all variant classes; applies only `className`    |
| `label`            | `string`                                              | String shorthand for `children`                         |
| `color`            | `AllColorVariant`                                     | Color from the full palette matrix                      |
| `rounded`          | `none\|sm\|md\|lg\|xl\|2xl\|3xl\|full`                | Border radius control                                   |
| `size`             | `xs\|sm\|md\|lg\|xl\|icon\|icon-xs\|icon-sm\|icon-lg` | Extended size system beyond shadcn                      |
| `as` (polymorphic) | `ElementType`                                         | Render as `<a>`, `Link`, or any element                 |

### `Avatar`

**shadcn:** Requires manual composition of `AvatarRoot` + `AvatarImage` + `AvatarFallback`. No built-in badge, group, or size system.

This project provides **two APIs**:

- **Prop-based API:** Use `Avatar` with `src`, `fallback`, `badge`, `size`, and sub-component props (`imageProps`, `fallbackProps`, `badgeProps`) for single-component usage.
- **Composition API:** Use `AvatarRoot`, `AvatarImage`, `AvatarFallback`, `AvatarBadge` for full control.

#### `Avatar` Props (not in shadcn)

| Prop            | Type                             | Description                                                 |
| --------------- | -------------------------------- | ----------------------------------------------------------- |
| `src`           | `string`                         | Image URL passed to `AvatarImage`                           |
| `alt`           | `string`                         | Alt text passed to `AvatarImage`                            |
| `fallback`      | `ReactNode`                      | Content for `AvatarFallback` — no manual composition needed |
| `badge`         | `ReactNode`                      | Pass `true` for status dot, or `ReactNode` for custom badge |
| `size`          | `'sm' \| 'default' \| 'lg'`      | Size variant controlling avatar dimensions                  |
| `imageProps`    | `Omit<AvatarImage.Props, 'src'>` | Props forwarded to `AvatarImage`                            |
| `fallbackProps` | `AvatarFallback.Props`           | Props forwarded to `AvatarFallback`                         |
| `badgeProps`    | `AvatarBadge` props              | Props forwarded to `AvatarBadge`                            |

```tsx
{
  /* Simple usage */
}
<Avatar src="/user.jpg" fallback="JD" />;

{
  /* With size and badge */
}
<Avatar src="/user.jpg" fallback="JD" size="lg" badge />;

{
  /* With custom badge color */
}
<Avatar src="/user.jpg" fallback="JD" badge badgeProps={{ className: 'bg-green-500' }} />;

{
  /* Custom fallback styling */
}
<Avatar fallback="AB" fallbackProps={{ className: 'bg-blue-500 text-white' }} />;
```

#### Extra Sub-Components (not in shadcn)

| Component          | Purpose                                                                 |
| ------------------ | ----------------------------------------------------------------------- |
| `AvatarBadge`      | Status indicator dot positioned at bottom-right corner; size-responsive |
| `AvatarGroup`      | Wraps avatars with overlapping `-space-x-2` layout and ring borders     |
| `AvatarGroupCount` | Shows overflow count (e.g. `+5`) styled to match grouped avatar sizes   |
| `AvatarGroupList`  | Props API for groups — accepts `items` array and `max` limit            |

#### `AvatarGroupList` Props (not in shadcn)

| Prop         | Type                     | Description                                        |
| ------------ | ------------------------ | -------------------------------------------------- |
| `items`      | `AvatarProps[]`          | Array of avatar configurations to render           |
| `max`        | `number`                 | Maximum visible avatars; overflow shows `+N` count |
| `countProps` | `AvatarGroupCount` props | Props forwarded to the overflow count indicator    |

```tsx
<AvatarGroupList
  items={[
    { src: '/user1.jpg', fallback: 'U1' },
    { src: '/user2.jpg', fallback: 'U2' },
    { src: '/user3.jpg', fallback: 'U3' },
    { fallback: 'JD' },
    { fallback: 'AB' },
  ]}
  max={3}
/>
```

### `Empty`

**shadcn:** Added October 2025 — ships `Empty`, `EmptyMedia`, `EmptyTitle`, `EmptyDescription`, `EmptyContent`.

This project matches the same sub-component set and extends `EmptyMedia` with an `icon` variant (themed icon container with `bg-muted`, rounded, and `size-8`). It also provides **two APIs**:

- **Compound API:** Use `EmptyRoot` with `EmptyHeader`, `EmptyMedia`, `EmptyTitle`, `EmptyDescription`, `EmptyContent` for full control over structure and composition.
- **Prop-based API:** Use `Empty` with `media`, `title`, `description`, `content`, and optional `headerProps` / `mediaProps` / `titleProps` / `descriptionProps` / `contentProps` for a single-component usage.

| Sub-component      | Purpose                                                                               |
| ------------------ | ------------------------------------------------------------------------------------- |
| `Empty`            | Prop-based root — accepts `media`, `title`, `description`, `content` (and \*Props)    |
| `EmptyRoot`        | Compound root wrapper — centers content with `flex flex-col items-center`             |
| `EmptyHeader`      | Groups media + title + description together                                           |
| `EmptyMedia`       | Media slot; `variant="default"` (transparent) or `variant="icon"` (muted bg, rounded) |
| `EmptyTitle`       | Heading text — `font-semibold text-sm`                                                |
| `EmptyDescription` | Muted helper text — `text-sm text-muted-foreground`                                   |
| `EmptyContent`     | Action area (buttons, links) rendered below the header                                |

**Compound API example:**

```tsx
<EmptyRoot>
  <EmptyHeader>
    <EmptyMedia variant="icon">
      <InboxIcon className="size-8" />
    </EmptyMedia>
    <EmptyTitle>No Results</EmptyTitle>
    <EmptyDescription>Try adjusting your search or filters.</EmptyDescription>
  </EmptyHeader>
  <EmptyContent>
    <Button onClick={handleClearFilters}>Clear Filters</Button>
  </EmptyContent>
</EmptyRoot>
```

**Prop-based API example:**

```tsx
<Empty
  media={<InboxIcon className="size-12" />}
  mediaVariant="icon"
  title="No Results"
  description="Try adjusting your search or filters."
  content={<Button onClick={handleClearFilters}>Clear Filters</Button>}
/>
```

### `Field`

**shadcn:** Form field primitives (when present) are typically low-level. This project ships a full **Field** family: `Field`, `FieldLabel`, `FieldDescription`, `FieldError`, `FieldContent`, plus `FieldSet`, `FieldLegend`, `FieldGroup`, `FieldSeparator`, `FieldTitle`.

Two APIs are available:

- **Compound API:** Use `FieldRoot` with `FieldLabel`, `FieldContent`, `FieldDescription`, `FieldError` and pass the control (e.g. `Input`, `Select`) as children for full control.
- **Prop-based API:** Use `Field` with `label`, `description`, `error` / `errors` / `issues`, and pass the control as `children`; optional `labelProps`, `descriptionProps`, `errorProps`, `contentProps`. Supports `orientation="vertical" | "horizontal" | "responsive"`.

| Sub-component      | Purpose                                                                                            |
| ------------------ | -------------------------------------------------------------------------------------------------- | -------- |
| `Field`            | Prop-based root — accepts `label`, `description`, `error`/`errors`/`issues`, control as `children` |
| `FieldRoot`        | Compound root — `role="group"`, orientation variants                                               |
| `FieldLabel`       | Label (optionally `asChild` for Radix Slot)                                                        |
| `FieldContent`     | Groups control + description in horizontal layout                                                  |
| `FieldDescription` | Muted hint text                                                                                    |
| `FieldError`       | Error message or list; accepts `errors` array or `issues` (e.g. Zod)                               |
| `FieldSet`         | `<fieldset>` wrapper                                                                               |
| `FieldLegend`      | `<legend>` with `variant="legend"                                                                  | "label"` |
| `FieldGroup`       | Groups multiple fields                                                                             |
| `FieldSeparator`   | Divider (optional text)                                                                            |
| `FieldTitle`       | Title-style label                                                                                  |

**Compound API example:**

```tsx
<FieldRoot>
  <FieldLabel htmlFor="username">Username</FieldLabel>
  <Input id="username" placeholder="Enter username" />
  <FieldDescription>Choose a unique username for your account.</FieldDescription>
</FieldRoot>
```

**Prop-based API example:**

```tsx
<Field label="Username" description="Choose a unique username for your account." labelProps={{ htmlFor: 'username' }}>
  <Input id="username" placeholder="Enter username" />
</Field>
```

Horizontal layout with description:

```tsx
<Field
  orientation="horizontal"
  label="Accept terms"
  description="You must accept the terms to continue."
  labelProps={{ htmlFor: 'terms' }}
>
  <Checkbox id="terms" />
</Field>
```

### `Item`

**shadcn:** Added October 2025 — ships `Item`, `ItemMedia`, `ItemContent`, `ItemTitle`, `ItemDescription`, `ItemActions`, `ItemGroup`, `ItemSeparator`.

This project extends with `variant`, `size`, `asChild`, and two extra sub-components: `ItemHeader` (section heading) and `ItemFooter` (metadata row). Two APIs are available:

- **Compound API:** Use `ItemRoot` with `ItemMedia`, `ItemContent`, `ItemTitle`, `ItemDescription`, `ItemActions`, `ItemHeader`, `ItemFooter` for full control (e.g. `asChild`, custom order).
- **Prop-based API:** Use `Item` with `header`, `media`, `mediaVariant`, `title`, `description`, `actions`, `footer`, and optional `*Props` for sub-components.

| Prop      | Values                        | Description                                            |
| --------- | ----------------------------- | ------------------------------------------------------ |
| `variant` | `default`, `outline`, `muted` | Border and background treatment                        |
| `size`    | `default`, `sm`, `xs`         | Padding and gap scale                                  |
| `asChild` | `boolean`                     | Renders as child element (e.g. `<a>`) via Radix `Slot` |

| Sub-component     | shadcn   | Purpose                                                                    |
| ----------------- | -------- | -------------------------------------------------------------------------- |
| `Item`            | ✓        | Prop-based root — accepts `media`, `title`, `description`, `actions`, etc. |
| `ItemRoot`        | ✓        | Compound root wrapper with variant/size                                    |
| `ItemMedia`       | ✓        | Media slot; `variant`: `default`, `icon`, `image`, `avatar`                |
| `ItemContent`     | ✓        | Flex column for title + description                                        |
| `ItemTitle`       | ✓        | Bold item label, line-clamped                                              |
| `ItemDescription` | ✓        | Muted helper text, line-clamped                                            |
| `ItemActions`     | ✓        | Right-aligned action buttons                                               |
| `ItemGroup`       | ✓        | Groups multiple items                                                      |
| `ItemSeparator`   | ✓        | Divider between items                                                      |
| `ItemHeader`      | ✗ custom | Section heading row — uppercase, tracking-wide, muted                      |
| `ItemFooter`      | ✗ custom | Metadata/timestamp row — small, muted                                      |

**Compound API example:**

```tsx
<ItemGroup>
  <ItemHeader>Recent Activity</ItemHeader>
  <ItemRoot variant="outline">
    <ItemMedia variant="icon">
      <BellIcon />
    </ItemMedia>
    <ItemContent>
      <ItemTitle>Security Alert</ItemTitle>
      <ItemDescription>New login from unknown device detected.</ItemDescription>
    </ItemContent>
    <ItemActions>
      <Button size="sm" variant="outline">
        Dismiss
      </Button>
    </ItemActions>
  </ItemRoot>
  <ItemSeparator />
  <ItemRoot asChild>
    <a href="/settings">
      <ItemMedia variant="icon">
        <SettingsIcon />
      </ItemMedia>
      <ItemContent>
        <ItemTitle>Account Settings</ItemTitle>
      </ItemContent>
    </a>
  </ItemRoot>
  <ItemFooter>Last updated 5 minutes ago</ItemFooter>
</ItemGroup>
```

**Prop-based API example:**

```tsx
<Item
  media={<BellIcon className="size-4" />}
  mediaVariant="icon"
  title="Security Alert"
```

A fully custom toast notification system built without the `sonner` library. Includes a custom `Observer` pattern for state management, custom swipe-to-dismiss, stacking, and rich notification types.

> **Note:** This is separate from the `Sonner` component. Use `Sonner` if you want the `sonner` library integration. Use `Toast`/`ToastProvider` for the fully custom implementation.

#### `ToastProvider` Props

| Prop            | Type                                                                                              | Description                            |
| --------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `position`      | `'top-left' \| 'top-right' \| 'bottom-left' \| 'bottom-right' \| 'top-center' \| 'bottom-center'` | Toast position on screen               |
| `theme`         | `'light' \| 'dark' \| 'system'`                                                                   | Theme mode                             |
| `richColors`    | `boolean`                                                                                         | Color-coded backgrounds per toast type |
| `closeButton`   | `boolean`                                                                                         | Shows close button on each toast       |
| `expand`        | `boolean`                                                                                         | Expand all toasts on hover             |
| `duration`      | `number`                                                                                          | Default toast duration in milliseconds |
| `gap`           | `number`                                                                                          | Gap between stacked toasts             |
| `visibleToasts` | `number`                                                                                          | Maximum visible toasts                 |
| `offset`        | `string \| number`                                                                                | Distance from viewport edge            |
| `dir`           | `'rtl' \| 'ltr' \| 'auto'`                                                                        | Text direction                         |
| `loadingIcon`   | `ReactNode`                                                                                       | Custom loading spinner                 |

#### `toast` API

| Method             | Description                                           |
| ------------------ | ----------------------------------------------------- |
| `toast(msg)`       | Default notification                                  |
| `toast.success`    | Success notification with check icon                  |
| `toast.error`      | Error notification with X icon                        |
| `toast.warning`    | Warning notification with triangle icon               |
| `toast.info`       | Info notification with info icon                      |
| `toast.loading`    | Loading notification with spinner                     |
| `toast.promise`    | Promise-based toast with loading/success/error states |
| `toast.custom`     | Fully custom JSX toast                                |
| `toast.show`       | Headless toast with custom styling                    |
| `toast.dismiss`    | Programmatically dismiss a toast                      |
| `toast.getHistory` | Get all toasts (including dismissed)                  |
| `toast.getToasts`  | Get only active (non-dismissed) toasts                |

```tsx
import { toast, ToastProvider } from '@paalstack/react-providers/ToastProvider';

{
  /* In layout */
}
<ToastProvider>
  <App />
</ToastProvider>;

{
  /* Trigger toasts */
}
toast.success('Saved!');
toast.error('Something went wrong');
toast.promise(fetchData(), {
  loading: 'Loading...',
  success: (data) => `Loaded ${data.name}`,
  error: 'Failed to load',
});
```

## Part 3: Layout Components

All layout primitives live in `@paalstack/react-ui` (exported from the `packages/layouts` package). Every layout component is **polymorphic** — it accepts an `as` prop to render as any HTML element — and extends `BoxProps` which provides `bg`, `textColor`, `borderColor`, and `fontSize` shorthand props on top of all standard HTML attributes.

---

### `Box`

The foundational primitive that every other layout component builds on.

| Prop            | Type            | Description                                                                              |
| --------------- | --------------- | ---------------------------------------------------------------------------------------- |
| `as`            | `ElementType`   | Render as any HTML element (`div`, `section`, `article`, `button`, etc.) — default `div` |
| `bg`            | `TailwindColor` | Background color shorthand                                                               |
| `textColor`     | `TailwindColor` | Text color shorthand                                                                     |
| `borderColor`   | `TailwindColor` | Border color shorthand                                                                   |
| `fontSize`      | `TailwindSize`  | Font size shorthand                                                                      |
| `withComponent` | `(as) => Box`   | Factory method to create a pre-bound element variant                                     |

```tsx
<Box>Default div</Box>
<Box as="section" bg="blue" textColor="white" className="p-4 rounded-lg">Section</Box>
<Box as="button" onClick={handleClick}>Button</Box>

// Create pre-bound element variants
const BoxButton = Box.withComponent('button');
```
